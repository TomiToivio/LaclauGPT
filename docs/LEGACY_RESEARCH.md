# Legacy research integration

This public repository intentionally does not publish project-specific code, codebooks, data mappings, storage integrations, or reprocessing scripts from earlier institutional research projects.

The reusable parts of that work have been generalized into the canonical LaclauGPT pipeline, schemas, collectors, prompts, visualization components, and configuration interfaces. Historical project-specific material is treated simply as **legacy research material** in the public repository.

## Public boundary

The public repository may contain generic pipeline/collector code, conceptual codebooks and schemas, synthetic examples, generic multimodal interfaces, configuration templates, and methodological lessons.

The public repository should not contain project-specific datasets, subject/account lists, empirical actor mappings, internal seed codebooks, storage layouts, manifests, reprocessing jobs, HPC allocation details, or empirical prompt context from earlier institutional studies.

Any retained institutional legacy material belongs in controlled storage or another access-controlled location and remains subject to the originating project's governance, ethics, data-protection, licensing, and publication rules.

## Naming rule

Public code and documentation should use `legacy` when referring to reusable functionality originating in earlier research integrations. The earlier project codename should not be used as a current public project identifier.

This sanitization applies to the current public branch. Git history is not rewritten automatically; historical remediation should be undertaken separately if institutional review requires it.
