### New defect found and fixed: the Commission's dates never parsed (Data-Collection #362)

The collection cycle has been reporting one warning per cycle that deserved a closer look: a record stored with `handoff.published_at = null` and therefore permanently unanalysable, attributed to `eu_ai_policy`. Reproduced against the live page with the repo's own code: the European Commission's digital-strategy pages publish `<time datetime="14 October 2026">`, `web_fetch._published` picks that literal string up, and `parse_source_time` returns `None` because `_SITE_DATE_FORMATS` covers only ISO 8601, RFC 2822 and numeric slash/dot stamps.

- Issue: **Data-Collection #362** (reproduction, observed versus expected, environment and commit sha all recorded).
- Fix: one named format `"%d %B %Y"` added to `_SITE_DATE_FORMATS`, with a comment naming the publisher, plus a pinned test module covering the production string, the zero-padded variant, the handoff reaching `published_at`, and the fact that a day-less stamp (`"October 2026"`) is still refused and counted rather than silently accepted.
- Tests: the new module and the neighbouring #295 date contracts pass (12 tests); full suite green (exit 0, 1,049 tests); Collection contract checks pass under the repository virtualenv.
- Pull request: **Data-Collection #363**, open against `main`.
