### Fix advanced this run

**#413 (Data-Analysis) - X stratum dies in media staging.** `StagedObject.retriable`
is `status == "failed"`, and `stage()` classified *every* download exception that
way, so `S3ArtifactStore.download_ref`'s `ValueError` for a reference outside its
bucket ("permanent classification error") was retried as transient. The worker
aborts a task on any retriable staging item, so all 1,172 analysis-ready X records
aborted before the first model call. Fixed on branch
`fix/413-store-rejected-ref-is-permanent`: a store-refused reference is now
`status="rejected"`, non-retriable, with the offending reference named in the log
(previously only the sha256 cache key was printed, so the refusal was unreadable
from the log). Verified against the real `S3ArtifactStore.download_ref` with a
stub client: relative ref -> `rejected`, `s3://` ref stages, worker's retriable
list empty. 1,263 tests pass / 1 skipped, contract checks green, PR **#415** open
with CI green on 3.11/3.12/3.13.

Deliberately left open on #413: the upstream half - Collection writing a
capture-side relative path into `source.raw_ref` at all - which is a data-quality
decision for Tomi, not a staging bug.
