### Root cause: the shared object store has been read-only for 17 days

Read access to the shared Allas-backed object store still works, but the bucket contents are
**byte-for-byte identical to the 2026-10-30 and 2026-11-10 readings**:

```
objects: 20739    bytes: 65600974740 (61.10 GiB)
```

Zero bytes have been accepted in 17 days. This is the same exhausted-quota condition already
tracked in Data-Collection **#396**, and it now explains the media failures as well: the
collector survives by writing records and marking raw envelopes
`raw_capture_pending = "quota_exhausted"`, while the media runner has no such fallback and
hard-fails.

The provenance hole is growing while the store stays full:

| Reading | Records | `raw_capture_pending` |
| --- | --- | --- |
| 2026-11-10 (from #396) | 10,636 | 946 (8.9 %) |
| 2026-11-16 (this run) | 11,149 | 1,448 |

That is +502 unreferenced raw captures in six days, now 13.0 % of the corpus. Every one of
them carries text and a citation but no preserved raw envelope.
