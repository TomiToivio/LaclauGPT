New technical finding this run: **the collection path has no disk spool.** Searching the
Data-Collection tree for any spool, outbox, queue or pending buffer directory returns

files. Every capture that would have happened in these 81 hours was attempted against the
store and dropped. This is therefore not a delayed pipeline but a permanent loss of the
outage window, which distinguishes it from a normal backlog and raises the cost of leaving
it running.

Recovery will also need capacity headroom. The analysis queue has accumulated while the
worker refuses to claim: roughly 41k entries on the analysis-ready stream, 9k on the task
stream and 565 on the dead-letter stream. The consumer group's last delivered entry is
still 2026-11-16 19:06 UTC, i.e. frozen since the break. When the store returns, the drain
should be sized deliberately rather than by raising the bounded task count blindly, and
the dead-letter stream deserves a read before anything is replayed.
