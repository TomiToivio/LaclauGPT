### Defect found and fixed this run: the preflight hid the cause

The analysis preflight reported only `type(exc).__name__` for object-store failures. Every S3
refusal is a `botocore` `ClientError`, so the provider code was discarded: for 59 cycles the
log said `"error": "ClientError"` and `["object store unreachable", "object store is not
writeable"]` for a store that was up and full. The collector was naming `QuotaExceeded` per
object the whole time; the gate the reports quote was not.

- Issue: **Data-Analysis #408**
- Fix: **PR #409** - `_s3_failure_detail()` carries `error_code` and `http_status` from the
  botocore response (no message, URL, key or credential), quota gets its own problem line,
  other provider codes are appended, and `object store unreachable` now means a real
  transport failure. Fail-closed behaviour unchanged.
- Verified live, not only in tests: the same check against the running configuration now
  returns `error_code: QuotaExceeded, http_status: 403`.
- 5 new tests, full suite green on 3.11/3.12/3.13, ruff clean, contracts pass.

- **arXiv 2610.39019, "Author-Informed Stance Detection: A Dataset and Findings"** (28 Oct 2026,
  Schlachet-Drukerman and Minkoff, University of Haifa). Human annotators and pretrained LLMs both
  perform poorly at inferring an author's leaning and stance from single tweets; supplying author
  context improves both, most sharply on sarcastic posts; author-informed fine-tuning beats
  standard fine-tuning and beats human performance. *Preprint, dataset available on request.*
  Directly relevant to §4.2's speaker-attribution and control-case evaluation - "a text quoting an
  ideology to reject it" is the failure mode this line of work measures, and the finding that
  author context is what resolves it is an argument for keeping source context in the record
  rather than stripping it in preprocessing.
