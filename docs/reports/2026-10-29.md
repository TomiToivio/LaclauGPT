### Root cause: the Allas quota is exhausted, not the pipeline

A 20-byte probe write to the shared AI26 bucket is refused:

```
An error occurred (QuotaExceeded) when calling the PutObject operation: Unknown
```

The same process reads the bucket successfully (`head_bucket` 200, 20,739 objects,
65.6 GB / 61.1 GiB stored). So credentials, endpoint, bucket policy and networking are fine;
only the write quota is gone. The probe object was deleted again; no other object was touched.

Consequences, measured in this run:

* **Collection.** Every source outcome reads `reason: object_store_or_database_unavailable`
  with `QuotaExceeded` on the raw-envelope upload, so `records_collected: 30` and
  `records_synced: 0` each cycle. That is about 330 records fetched and dropped over the
  11 failed cycles since 2026-10-28 19:10. The deployed checkout has no local capture
  mirror (no raw file written under `data/` since 2026-10-28 18:00), so nothing is staged
  for a later retry.
* **Analysis.** Preflight reports `"problems": ["object store unreachable", "object store is
  not writeable"]`, `"status": "invalid"`, and each cycle ends with
  `ERROR: preflight reported a configuration problem; refusing to claim tasks`. Eleven such
  refusals between 2026-10-28 19:05 and 2026-10-29 05:05. The queue is not the problem and
  no cursor was touched.
* **Not restarted.** Restarting either wrapper cannot clear a storage-side quota refusal, and
  an analysis restart would only re-refuse at preflight. The visualization and media stages
  needed nothing.
* **Local disks are not the cause:** `/mnt/workspace` 75% used (227 G free), `/` 80%
  (179 G free).

Analysis log noise in the last healthy cycles remains what it always was - `structured
generation truncated` / `structured parse failed` retries of a thinking model - and is not
part of this failure; the authoritative signal is the missing `analysis end` line.
