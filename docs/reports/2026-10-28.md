### What was fixed

**One real defect found and closed: the collection stage was running an unreviewed branch.**

The host that executes the hourly collection wrapper had the repository checked out on
`feat/361-language-backfill` (2 commits ahead / 4 behind `origin/main`) instead of `main`.
Because the wrapper runs the working tree, the deployed collector was executing pre-merge
code whose `rss.py` **reverts** the merged RSS full-text language detection from #367 — it
fed `resolve_language()` only the title and summary instead of the longest available
publisher content. The stage's own runtime self-check had been reporting the drift hourly
(`runtime code ... STALE ... not the reviewed revision`) but the cycle deliberately
continues ("collecting anyway"), so it never surfaced as a stage failure.

Effect visible in the logs before the fix: records stored without a language label with
reason `insufficient_text` (4 in the 04:10 cycle, 2 in the 05:10 cycle) — the same symptom
issue #361 is about.

Fix (operational only): returned the checkout to `main` and fast-forwarded to
`origin/main` (`3d7539e`). Contracts and the full test suite pass on that revision, and the
runtime self-check went from `STALE (1 of 5 checks)` to `in sync (0 of 5 checks)`. Verified
live on the next scheduled cycle: 06:10 ran from `origin/main` with no drift line,
`status: ok`, 0 errors, 0 warnings, manifest in sync — first cycle in over a day without the
language warnings. Issue **#370** opened with the evidence and closed with the verification.
