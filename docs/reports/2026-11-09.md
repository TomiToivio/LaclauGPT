### New coverage gap: the AI26 web stratum has been empty since 2026-11-02 (#406)

Eleven `web_source` rows are active in the AI26 manifest (Anthropic news, Meta AI, Google DeepMind, Microsoft AI, Dario Amodei essays, DAIR, EU AI policy, FCAI, the Finnish government, and two data-centre campaign sites). Their queue entries have sat at `pending`, `attempts=0`, `last_error=null` since the shared queue was created on 2026-10-28, and no cycle has ever claimed one. Over the last five days every executed job in `source_outcomes[]` is a Bluesky or Mastodon account; the web stratum has produced zero documents for twelve days.

The cycle cannot show this: it claims six of the fifteen claimable jobs, reports `status: ok`, `errors: []` and `deferred_by_tick_limit: 0`. The two surviving `scholarly_query` rows are starved by the same mechanism, and the six remaining cancelled ones are a separate decision.

Diagnosis so far: the claim sort is `(priority, created_at)` and every queue document carries the same priority and the same `created_at` to the microsecond, so the winner is whichever index Mongo chooses; the `(status, kind, priority, created_at)` index orders that tie by `kind`, which puts `bluesky_account` first and `web_source` last on every cycle. A read-only replay with that hint reproduces the account-first order, an unhinted run does not, and a mongomock copy of the same documents claims six `web_source` jobs - so the live cause is plausibly plan-dependent ordering, but not proven.

No code was changed. A speculative ordering fix would be cosmetic if the live cause is something else, and the choice between "fix the scheduler", "declare web out of scope for Phase 1" and "wait for the scholarly decision" belongs to the study owner. Issue #406 records the evidence, the ruled-out list and the reproduction so the decision can be made without re-deriving any of it.
