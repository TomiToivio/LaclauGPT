### Work done this run - #234 is now guarded (PR #235)

The live dashboard had drifted off `origin/main` three times (#176, #185, #234) and each
time the deploy preflight stayed green: it verified that a checkout existed and that the CLI
was installed, not **which** commit would be served. The dependency half of #234 was the same
blindness - `networkx` was declared in `pyproject.toml` but absent from the serving venv,
and the stale editable-install metadata was exactly the source that hid it.

PR #235 implements option (a) from the issue with `deploy/preflight-checkout-ai26.py`,
called from `deploy/preflight-laskin-ai26.sh` right after the CLI check:

- the serving checkout must be on `main` **and** equal to `origin/main`, otherwise the
  failure names the served SHA against upstream with ahead/behind counts;
- every requirement in `[project].dependencies` must be installed in the serving venv at a
  satisfying version, read from `pyproject.toml` rather than from install metadata;
- intentional branch deploys remain possible via the logged overrides
  `LACLAUGPT_VIS_ALLOW_GIT_DRIFT=1` and `LACLAUGPT_VIS_GIT_FETCH=0`.

12 tests cover behind/ahead drift, a feature branch, a missing `origin/main`, the override, a
missing dependency, an unsatisfied version, extras and environment markers being ignored, and
this checkout satisfying its own core dependencies. Full suite 581 passed; the real preflight
on Laskin passes with both new `OK:` lines.

### A second worktree claims `main` (new issue #236)

Found while putting the live checkout back on `main` after my branch: the live-steps dashboard
is served from a **second git worktree of the same clone**, registered during this
run, and it holds branch `main`. The `:8501` checkout the AI26 unit serves therefore cannot
check out `main` at all:

```
fatal: 'main' is already checked out at '<live-steps worktree>'
```

The documented refresh in `docs/AI26_LASKIN_DASHBOARD.md` fails at step two, and the only way
back was the undocumented `git checkout --ignore-other-worktrees main`. A routine deploy step
can thus leave `:8501` on a non-`main` commit - precisely the drift class of #176/#185/#234. The
new guard caught it immediately (`branch 'fix/234-deploy-drift-guard'`, `1 ahead / 0 behind`),
the checkout was restored to `c8f2509` == `origin/main`, and the service kept serving 200
throughout. Filed as **#236** with a request to give the live-steps deployment its own branch or a
detached SHA. The worktree's working tree carries another session's staged edits and was left
untouched.
