### Opened this run

**#413 (Data-Analysis) - X analysis dies in media staging: a non-S3 `source.raw_ref` raises `ValueError`
that is retried as transient.** The single X task seeded by #412 is claimed six times and writes no
result. The record exposes two object references: the valid `s3://` payload and a capture-side relative
path (`raw/x/.../capture-*.ndjson`) carried in `source.raw_ref`. `download_ref` refuses anything outside
the configured bucket with `ValueError`; `stage()` records it as `download_failed`, and because
`StagedObject.retriable` is defined as `status == "failed"`, the worker retries a permanent
classification error three times and parks the task. The operator message prints only a sha256 cache key,
so the log cannot name the refused reference. Scope: `source.raw_ref` is present and non-`s3://` on 9,984
stored AI26 records, so the same trap is armed corpus-wide; it only fires on records that carry a real
object next to the bad path.

Two candidate fixes are laid out in the issue and neither was implemented: normalising or dropping
non-absolute references plus a permanent-vs-retriable classification on the analysis side, or writing
`source.raw_ref` as a real object key on the collection side. Both change a contract, so they wait for a
decision.
