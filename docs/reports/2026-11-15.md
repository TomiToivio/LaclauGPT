### Issue worked: #433 → PR #434

**#433** (the #429 backfill slice drains the closed X stratum first) is unchanged today:
`backfill_limit=3`, `backfill_published=3`, `backfill_examined=150` per cycle, with the
oldest-published cursor still inside September, while 1,140 ready X documents remain
never-analysed.

The issue lists three remedies as an owner decision. This run implemented the smallest one
as the issue itself described it — "a platform exclusion form on the backfill pass, default
off so nothing changes until it is switched on": **PR #434**.

- `ready_handoff_query()` accepts `exclude_platforms` and renders `source.platform:
  {$nin: [...]}`, composing with the existing single-platform scope.
- The oldest-first reader passes it through; `seed_ready_tasks()` applies it to the backfill
  walk **only**, so keeping the live tiers fresh is unchanged.
- Switch: `LACLAUGPT_AI26_BACKFILL_EXCLUDE_PLATFORMS` (CLI `--backfill-exclude-platforms`),
  comma-separated, **empty by default** — the pipeline behaves exactly as before until a
  closed platform is named.
- A handoff reader that cannot honour the keyword keeps its old ordering and logs a warning
  instead of failing the cycle.
