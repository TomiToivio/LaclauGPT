### Issue worked: #217 (Data-Collection) - partial tick swallowed the end marker

Fixed in PR #220 (branch `fix/issue-217-partial-tick-end-marker`, base `7b3f6e8`),
CI green.

`scripts/run_ai26_laskin_collect.sh` runs under `set -euo pipefail` and echoed its
`AI26 Laskin collection end` marker *after* the runner call, but the runner returns
exit 1 whenever any source recorded an error. A single transient upstream failure
(e.g. arXiv HTTP 429) therefore aborted the wrapper before the end marker, so a tick
that had collected its records normally read as a silently stopped stage.

Fix: capture the runner status, always emit the end marker (annotated
`runner_status=1 (tick partial; ...)` on a partial tick), and still propagate the
non-zero exit for cron/CI. The change is confined to the shell wrapper, so it does
not collide with the #212 retry PR that edits `ai26_laskin_runner.py`.

Verification: new `tests/test_issue_217_partial_tick_marker.py` executes the real
wrapper against a stubbed runner; reverting only the wrapper reproduces the original
symptom (missing end marker), with the fix all cases pass. Full suite 444 passed,
`ruff check` clean, contracts green, `bash -n` clean, PR CI fully green.

### 2. Scientific publications — genuinely new and AI26-relevant

- **Inductive Claims Extraction at Scale (arXiv:2610.05275v2, Univ. of
  Edinburgh, 4 Oct 2026).** An LLM pipeline that **inductively extracts and
  catalogues claims** as the unit of political-discourse analysis (declarative,
  single-clause, factual-to-evaluative statements carrying an interpretation of
  reality), applied to two Twitter corpora (2020 US election; 2022 World Cup).
 Evaluated properly: **precision and recall against hand-annotated samples,
  ablation studies of pipeline components, qualitative error analysis**; the
  output is a structured *claims catalogue* usable with SNA. *Credible
  (preprint, strong evaluation).* **This is the closest published relative of
  the LaclauGPT Phase 1 method that has appeared in this watch so far.** It
  independently converges on extracting claims as the analysis unit rather than
  topics or stance, which is precisely the Laclau-style demand/claims level —
  and its evaluation protocol (annotation-anchored P/R, ablations, error
  analysis) matches the validation bar AI26 already sets for itself. High
  value for Phase 2 comparative grounding (position LaclauGPT's
  articulation/equivalence chain analysis relative to it) and for Phase 3
  (borrow the ablation/error-analysis template for our own pipeline's papers).
  One methodological divergence worth recording: their catalogue treats claims
  as retrievable items, not as *elements entering relations of
  equivalence/difference* — the discursive-theoretic step remains ours.

- **MASC: A Multi-Agent Self-Calibration Framework with Latent Construct
  Alignment for Consistent Client Role-Play (arXiv:2610.08250, 6 Oct 2026).**
  *Credible (preprint).* Targets the known problem that LLM-simulated survey
  interviewees are unstable role-players; self-calibration across a multi-agent
  system aligns responses to latent constructs. Relevance for AI26: if
  human-in-the-loop validation ever needs synthetic interviewee panels or
  persona-based robustness checks for the coding protocol, this is the
  construction to cite — and its "latent construct alignment" framing is a
  direct answer to the validity question every LLM-coding pipeline faces
  (Phase 2).

- **Counting Moves, Weighing Voices: Bayesian Dialectical Argumentation for
  Calibrated Multi-LLM Councils under Perplexity (arXiv:2610.02005, 1 Oct
  2026).** *Credible (preprint).* Calibrated aggregation of several LLM judgements
  as a weighted council rather than majority vote. Relevance: an alternative
  aggregation design for the multi-LLM cross-coding checks that the validation
  protocol sketches; complements 10-07's JEV-vs-LLM calibration finding
