### Issue worked: #217 (Data-Collection) - partial tick swallowed the end marker

Fixed in PR #220 (branch `fix/issue-217-partial-tick-end-marker`, base `7b3f6e8`),
CI green.

`scripts/run_ai26_laskin_collect.sh` runs under `set -euo pipefail` and echoed its
`AI26 Laskin collection end` marker *after* the runner call, but the runner returns
exit 1 whenever any source recorded an error. A single transient upstream failure
(e.g. arXiv HTTP 429) therefore aborted the wrapper before the end marker, so a tick
that had collected its records normally read as a silently stopped stage.

Fix: capture the runner status, always emit the end marker (annotated
`runner_status=1 (tick partial; ...)` on a partial tick), and still propagate the
non-zero exit for cron/CI. The change is confined to the shell wrapper, so it does
not collide with the #212 retry PR that edits `ai26_laskin_runner.py`.

Verification: new `tests/test_issue_217_partial_tick_marker.py` executes the real
wrapper against a stubbed runner; reverting only the wrapper reproduces the original
symptom (missing end marker), with the fix all cases pass. Full suite 444 passed,
`ruff check` clean, contracts green, `bash -n` clean, PR CI fully green.

### Verification of #327 (read-only, against the live store)

Reproducing `rearm_terminal_failure_if_budget_increased`'s selection predicate against

- **50 correctly skipped** — 7 already at 16384, 43 with no recorded budget or another

That matches the issue's own analysis exactly, and the guard rails hold (one-shot

### Gap closed — PR #329 (docs only)

Neither #327 nor #321 updated the operator docs, and one of them **forbade what the code
now does**:

- `docs/issue-300-remediation.md` said *"Do not automatically rearm on an hourly cycle."*
- `docs/REDIS_TASK_WORKER.md` described terminal quarantine as reversible only via

Both now describe the shipped behaviour and its guard rails, and name the regression
tests. **Docs only; no code changed.** 925 passed, 1 skipped; all Analysis contract
checks pass; PR #329 open for merge.

### Open measurement — the decode path (from #321, now on the record)

Measured across the 168 documents that died at the 8192 ceiling: **0.479 characters per
spent token** on average, against **3.10** measured on a healthy call to the same model
— and one document emitted **4 characters** from an 8192-token budget. Far too little
content to have exhausted the budget honestly.

So the re-arm is safe (bounded, one-shot, provenance-preserving), but the **recovery
rate** of a mass re-drive should be measured on a bounded sample before concluding how
much of the backlog is genuinely recoverable. Recorded in the remediation doc as an open
measurement, not a settled mechanism.
